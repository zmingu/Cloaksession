# 快手小店账号初始化二开

## 状态与目标

- 状态：**planning**。本文与 design.md、implement.md、implementation-ready.md 是本轮规划提案，尚待用户最终批准；不代表授权 task start、产品实现或真实账号权限写入。
- 目标：检测到快手小店有效账号ID后，每次刷新身份与本地头像，首次获取主体资料（本地OCR兜底），首次关闭全部全自动发布主权限，失败可补做。
- 技术基线：Tauri + Rust/chromiumoxide；复用现有 identity、business_accounts、TaskPage、registry。Chromix 启动桥暂留，不新增 Node 业务 worker。
- R1 真实后端身份检测与本地头像缓存已验收；UI视觉未单独核实，不能将整项 AC1 直接勾为完成。主体档案/OCR/切片仍未实现。

## Requirements（保留原需求ID）

### R1 账号识别（每次登录）
- R1.1 扫码登录 login.kwaixiaodian.com 成功跳转 s.kwaixiaodian.com/zone/home 后，自动获取快手ID与头像。
- R1.2 快手ID与头像补充式展示在 Profile 卡片（不替换现有 emoji/名称）。
- R1.3 每次登录重新刷新（覆盖旧值）。
- R1.4 头像需保存到本地附件目录（非仅网页链接），供离线展示。

### R2 主体资料获取（仅首次）
- R2.1 进入资质管理 s.kwaixiaodian.com/zone/shop/info/qualification。
- R2.2 优先读「主体信息」Tab 明文姓名、身份证号。
- R2.3 主体信息无资料或不完整时，转「达人主体」Tab 尝试获取；真实标签是「达人主体信息」。
- R2.4 达人主体仍拿不到完整文字时，对身份证照片做本地 OCR。
- R2.5 OCR 结果自动校验（身份证号格式/校验码/出生日期；与页面可见部分比对）+ 人工确认（对照照片）两重保护。
- R2.6 自动校验通过仍需人工确认后方可标记「已核对」。
- R2.7 仅首次获取，后续登录不自动重复（按快手ID记录完成状态）。
- R2.8 存档范围最小：姓名、身份证号、证件照片 + 快手ID + 来源/核对状态。
- R2.9 详情页查看资料与照片；一键复制「快手ID+姓名+身份证号」；待核对状态允许复制但标注「未核对」。
- R2.10 存储：本地 SQLite（文本字段）+ 本地附件目录（证件照片/头像）；明文不加密。
- R2.11 删除浏览器环境不删除账号档案，仍可搜索/查看/复制。

### R3 切片权限设置（仅首次）
- R3.1 进入直播切片 s.kwaixiaodian.com/zone/short-video-b/slice → 点设置入口；旧称「去设置」，真实样本为「修改设置」。
- R3.2 关闭所有全自动发布权限。当前已验证集合是「全自动发布权限」区四个主 checkbox，详见 design.md；不包括智能生产 switch、限量 checkbox、radio 或数值设置。
- R3.3 仅首次设置，后续登录不自动重复（按快手ID记录完成状态）。
- R3.4 风险：平台或人工可能再次开启，届时不会被自动纠正，需手动处理（用户已知悉）。

### R4 触发与执行
- R4.1 自动检测：软件检测到已登录即自动开始，不需手动点击、不先提示确认。
- R4.2 每个已打开的浏览器环境各自检测、各自初始化，互不干扰。
- R4.3 登录判定标准：能成功读出快手ID才算登录成功；读不到不动作、下轮再检测。
- R4.4 保留手动「重新检测/初始化」入口作为兜底。
- R4.5 OCR 需人工确认时不中断流程：先做完能做的，账号标「待核对」，事后在详情确认。

### R5 失败处理
- R5.1 某一步失败先自动重试。
- R5.2 仍失败则提示用户。
- R5.3 保留「未完成」状态。
- R5.4 下次登录/检测时补做未完成项。
- R5.5 失败提示以 Profile 卡片状态标记展示（如「初始化未完成」），点开看具体哪步；不弹窗打断。

## 本轮细化提案（待用户最终批准）

1. Windows首版用系统中文OCR；缺语言资源明确不可用，不自动下载、不转云端。必须真实集成，不以trait/占位实现验收。
2. 创建专用任务页，保留用户主页面；成功仅关闭任务自己创建页，失败保留自建页供排查。下次补做仍须重验账号/会话，不接管任意用户页。
3. 自动校验不过允许改正、允许标注未核对复制，不允许强行标记「已核对」。缺少可见比对片段应显示无法比对，而非虚构通过。
4. 首版仅支持已验证自然人字段（经营者/分销者）；企业或未知结构失败待处理，不猜法人或法律主体类型。

## 调研证据与剩余未知

完整证据见 [真实页面研究](research/live-page-structure-2026-10-01.md)。该研究只证明DOM结构，不证明实际证件内容、图片清晰度或权限保存行为。

- 主体样本：经营者姓名、18位形态证件号码可作为明文候选；达人样本姓名/证件号脱敏。必须限定激活Tab，不能读残留隐藏面板。
- 两类证件行各有2个同源HTTPS img；未读取像素/原图，受保护读取与清晰度未知。采集成功必须包含真实图片本地读取验证，否则未完成，不能仅凭URL/已加载标成功。
- 用户手动打开设置后已补齐四项checkbox结构；唯一switch是智能生产权限，必须排除。
- 未知保存语义留待实施阶段受控验证：没有保存按钮不代表已保存；不得盲点隐藏「确定」。需关闭后重读/刷新验证持久状态。
- 普通测试不在真实账号点击。自动关闭是产品目标，但最终真机写验收前仍需确认；该验收授权不是每次正常自动初始化的额外弹窗。
- 系统中文OCR引擎本机可创建，尚未测试识别准确率，也尚未集成产品；先用合成资料测试，不自动下载模型或读取真实证件。

## Out of Scope

- 快分销 CPS 加货架（cps.kwaixiaodian.com）及跟播助手开播前设置：第二批。
- 自动上车/小黄车、定时上下车、直播间互动：后续。
- 资料加密：用户明确不做，本批明文。
- 多账号批量编排：首版各环境独立；同账号去重是正确性约束，不是批量任务功能。
- 企业未知分支自动映射、云OCR、自动下载模型不在本轮提案内。
- **取代旧“本地OCR具体模型集成后置”条款**：本轮必须实现真实本地OCR闭环；技术候选待批准，效果与打包仍需验证。

## Acceptance Criteria（保留原AC编号）

- [ ] AC1 扫码登录成功后，Profile 卡片显示该账号快手ID与头像（补充式，未替换原名称/emoji）。后端/缓存已验收，UI视觉未单独核实。
- [ ] AC2 首次登录自动完成主体资料获取；后续登录不重复获取（按快手ID判定）。
- [ ] AC3 主体资料可在账号详情查看照片与文字，可一键复制「快手ID+姓名+身份证号」。
- [ ] AC4 OCR 结果标记「待核对」直到人工确认，确认后才标「已核对」；待核对可复制并标注。
- [ ] AC5 首次登录自动关闭切片全自动发布权限；后续登录不重复设置（按快手ID判定）。以持久回读而非点击返回作为完成证据。
- [ ] AC6 删除某浏览器环境后，该账号主体资料与证件照片仍可在软件中搜索/查看/复制。
- [ ] AC7 初始化某步失败时：自动重试→仍失败在卡片标记「未完成」→下次检测补做。
- [ ] AC8 同时打开多个环境时，各自独立检测与初始化互不干扰。
- [ ] AC9 主体资料存档为本地 SQLite + 本地附件，明文，删环境不删档案。
