# 快手小店只读身份检测

## Scope / source

`driver/identity/{mod.rs,extract.rs,extract.js,avatar.rs}` owns app polling, page decoding and local avatar caching. `registry.rs` owns per-process/session UUID slots, OnceCell attachment and cancellation. `commands/kuaishou_identity.rs` is thin IPC; persistence stays on LauncherCmd::Identity, using the original ProfileManager connection. No Node business worker, active-page routing, navigation, login, cookies/tokens, OCR or slicing-permission actions.

## IPC contract

- `kuaishou_identity_list()` -> Snapshot[]; only lists/project stored observations, never runs CDP.
- `kuaishou_identity_detect({profileId})` -> Snapshot; stopped/missing Profile returns closed without launch.
- `kuaishou_identity_avatar({avatarKey})` -> local `data:image/png|jpeg|webp|gif;base64,...` or null. No path or remote URL return.
- Snapshot camelCase fields: profileId, status (`unknown|detected|not-detected|conflict|closed|skipped|error`), platformUserId, nickname, avatarKey, checkedAt, lastSeenAt, message; nullable fields serialize explicit null. Tauri async State adapters wrap Result internally, without changing JS resolved values.
- `detected` means a valid ID was read on the exact shop origin, not backend authentication, initialization, or verified OCR. Every other status can carry last-success fields but must not imply current login.

## Read / lifecycle contract

Only HTTPS443 `s.kwaixiaodian.com`, no userinfo, exact hostname (not substring). Static JS reads only the username header selectors from jieger `subAccount/index.ts:200-257`; anchored 5..32 ASCII digits after ID label, nickname max80; returns URL and data in one evaluate. Rust validates the returned URL/ID again. All matching targets (maximum16) are read with TaskPage; differing IDs => conflict, identical IDs merge. Missing page and missing ID have distinct messages. Any page/JS/decoding/timeout error is error, never success.

Each TaskPage acquisition waits <=500ms, evaluation <=2s; CDP stage <=8s, avatar <=5s, work <=14s, each DB request <=2s, manual/auto request <=20s. Async cancellation cannot undo already sent CDP, but these requests are read-only. Registry has one pending OnceCell per process marker (startedAt:pid plus endpoint); same marker reuses original launch-network snapshot. Close/remove cancels; pending connections cannot reinsert after removal. Launcher prepares the slot before launch reply, so a stale reply cannot recreate a removed session.

Save checks current Arc slot, UUID/session_id, cancellation, reply/deadline, Profile existence and unchanged complete business state. The registry lock excludes remove during a synchronous DB transaction; no CDP/network work occurs on the launcher loop. Running liveness is rechecked on launcher read/list/save; Chromix process liveness uses its SDK supervisor flag (checked on read/list/save). List projects old UUID observations to unknown/closed after restart/relaunch. Nonshop binding or retained jinniu scope is skipped; manual ID mismatch is conflict, not a manual-data edit.

## Automatic monitor

App setup starts once using an atomic flag, not UI detect calls. Five-second ticks enumerate all initialized registry sessions (including UI/MCP-launched unbound profiles), rotate candidates, acquire at most four global permits and one RAII per-profile gate shared with manual detection. Busy work is skipped, not queued. Idle loop only owns Weak driver; shutdown/drop/app Exit cancels. Retry state prunes inactive profiles. No complex scheduler.

## Avatar boundary

Independent `kuaishou-avatars/` sibling of profiles.db, not a Profile directory. HTTPS443 yximgs.com/subdomains only, no userinfo, no redirects, <=2MiB streaming and request deadline, PNG/JPEG/WebP/GIF magic; no SVG/HTML/data URL. SHA256 content filename plus format extension, same-directory UUID temp and rename. Reads require a DB reference, safe hash key, regular bounded file, canonical parent, reparse/symlink rejection, no-follow flags on Windows/Linux/macOS, and matching content hash/magic before data URI.

Proxy comes from the launch snapshot, never edited live Profile values. Supported: explicit Profile HTTP/SOCKS5 proxy or simple top-level Chromix proxy object; per-profile options shallow override global. SOCKS uses remote DNS; HTTP proxy Basic credentials are only proxy auth, never origin Authorization/Cookie. Environment proxy/no_proxy/Node overrides, nested proxy layers, PAC/args/bypass/complex SDK overrides, or unresolved OS proxy with no explicit profile proxy => warning and skip download, **never silently direct connect**. ID detection stays detected on avatar failure. Current same-ID successful URL/key is reused; changed ID cannot inherit an old image; failure backoff 20..320s keyed by generation+ID+URL, URL/generation change retries.

Before any explicit proxy download, `extract::AvatarPage` tries the existing, fully loaded account-header `img` via detached canvas (PNG output). It retains the original detected target's TaskPage lease across local cache IO / proxy fallback. A separate probe composes the unchanged four-field EXTRACTOR; reads and rechecks exact account ID/currentSrc, HTTPS shop URL, image complete/natural dimensions, main-frame identity and `performance.timeOrigin`. No img src/crossOrigin mutation, new image/page, fetch, document screenshot, active switching or raw-CDP escape. Pixel reads cap each dimension at 2048, base64 at ceil(2MiB/3)*4; Rust estimates decoded size before strict STANDARD base64 decoding, then uses the same raster magic/hash/path cache. yximgs HTTPS443/no-userinfo allowlist applies to both paths; explicit .svg/.svgz addresses are rejected. Canvas output is re-encoded PNG, not source-file bytes or a DOM screenshot. Cross-origin taint/unavailable pixels falls back only to the existing explicit proxy or warning/skip. ID remains detected. Navigation/ID/URL/loading/session-generation changes discard the candidate; generation/current-slot and original DB guards remain authoritative at commit. Messages distinguish already-loaded browser pixels, explicit-proxy download and verified local reuse.

**Do not use Page.getResourceContent as a cache-only primitive.** The isolated Chrome 153 fixture observed this command return PNG while also requesting the main document again (Fetch counter 3→4, Network counter unchanged). A missing image URL returned -32000 without a new request, but that does not make a cache hit safe. No new cdp-driver resource API was added; existing controlled TaskPage::evaluate suffices for the safer canvas fallback. Its limited capability is intentional: a no-CORS avatar can still be unavailable when no explicit proxy is known.

## 2026-10-01 avatar GET amendment (supersedes the canvas-only limitation above)

Only the avatar boundary is extended by explicit user authorization. Canvas/local cache remain first. For AvatarRoute::Skip, use AvatarPage::read_network, not host reqwest: a fixed TaskPage invokes one browser-native public HTTPS yximgs GET (credentials omitted, redirect:error, no referrer). A non-universal isolated world prevents page fetch monkeypatching without changing CORS. Exact-URL Fetch response interception correlates Network requestId with main frame, GET and unique initiator sourceURL; only this response is read through Fetch.takeResponseBodyAsStream / IO.read (32KiB chunks, 2MiB aggregate, early content-length rejection). Reject redirects before follow, non200 and Location. No page image mutation, navigation or active selection. Original fetch is aborted; response bytes are not exposed to page JS. Raster magic/hash/path validation and all session/account/document rechecks remain unchanged. Explicit static proxy path remains as before; browser failure does not trigger a second download.

Cancellation/drop signals a bounded Rust cleanup worker; a separate session/target weak lock survives until cleanup finishes, preventing a successor avatar operation from racing old Fetch.disable. Abort only the owned isolated-world controller, close stream, fail owned request and disable exact interceptor; cleanup failure cannot produce success. Lost CDP replies are best effort, not guaranteed recall. Same-session arbitrary raw Fetch configuration is not supported concurrently; no existing production business Fetch interceptor is added/changed. Domain and byte limit constants now live in cdp-driver::avatar_resource. Public URL fragments are rejected too. Tests and remaining native/live acceptance are recorded in task results-avatar-browser-get.md.

## Tests / limits

Core serde tests, SQLite upgrade/reopen/delete/scope/mismatch tests, Tauri lifecycle/gate/scheduling/weak ownership/cache/proxy tests. `cdp-driver/tests/kuaishou_identity.rs` imports the production reader by path and reuses common peer for actual chromiumoxide routing/error/lock tests (no duplicated fixture, no reverse library dependency). Peer returns scripted values and does not execute JS. UI agent owns separate local DOM fixture checks. Real platform DOM, native app end-to-end and actual CDN/proxy traffic remain untested; magic validation is not full image decoding. Dynamic proxy changes after launch are not resolved.
