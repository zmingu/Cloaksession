# Internationalization (i18n) Guidelines

The app uses a lightweight in-house i18n layer at `crates/tauri-app/ui/src/i18n/`. No external i18n dependency (i18next/react-intl).

## Architecture

- `en.ts` / `zh-CN.ts` — typed dictionaries. `TranslationKey = keyof typeof en`. zh-CN is `Record<TranslationKey, string>`, so a missing zh key is a compile error.
- `translate.ts` — pure `t(key, params)` with `{{name}}` named-placeholder interpolation. Interpolation produces text nodes only; no HTML injection.
- `LanguageProvider.tsx` — React Context provider + `useLanguage` / `useT` hooks.
- `index.ts` — barrel.
- `dictionaries.test.mjs` — Node test asserting en/zh-CN identical key sets and identical placeholder sets per key.

## Language setting contract

- `AppSettings.language: AppLanguage` where `AppLanguage` is `zh-CN | en`, default `zh-CN`. **No `system` mode.**
- `AppSettings.language` is decoupled from `Profile.locale` (the browser `--lang` / `--accept-lang` fingerprint field). They are different concerns: the former drives the management UI; the latter drives the managed browser session.
- `RawSettings` reads the language field tolerantly (missing/null/unknown/wrong-type falls back to the default language only; it never clears other valid settings).
- IPC `settings_update` accepts known values; illegal explicit update returns an error; old clients omitting `language` keep the existing value.

## First paint and switching

- `main.tsx` reads settings before mounting the full UI (lightweight launch placeholder) to avoid a saved-English user seeing a full Chinese flash. Initial `index.html` lang is `zh-CN`; the provider syncs `document.lang` after settings load.
- On settings-load failure, fall back to Chinese with an actionable retry UI. The error boundary uses Provider-free module-level `t()` (it wraps the provider and must not depend on it).
- The Settings page saves language via the existing IPC; the global language updates only after server success. Repeat submits are disabled while saving. Switching does not unmount App or lose form input.

## Adding or changing UI strings

1. Pick a domain-prefixed semantic key (e.g. `nav.profiles`, `settings.mcp.title`, `errors.profileNotFound`). Never use a full English sentence as the key.
2. Add the key to **both** `en.ts` and `zh-CN.ts` in the same edit. The dictionaries test will fail on a key-set mismatch.
3. Use `{{name}}` named placeholders for interpolation. Never single-brace `{name}` — `translate()` only substitutes `{{...}}`.
4. Call `t('key')` or `const t = useT(); t('key', { param })` in components. For non-component pure functions, use module-level `t()` from `translate.ts`.

## Exception categories (never translate)

- `brand` — Cloaksession, CloakBrowser, Chromix.
- `protocol` — JSON/TOML keys, IPC command names, MCP tool names, enum wire values, URLs, file magic.
- `user-data` — profile names, tags, notes, nicknames, IDs, paths.
- `external` — third-party extension titles/descriptions, Web Store text, raw backend diagnostic strings.
- `keep-original` — keyboard key names (Escape, Enter), shortcut symbols (⌘ K), units, OS names.

## Backend and native prompts

- Do **not** modify the shared `MultizenError::Display` — MCP/log consumers depend on it. UI catches errors and renders an operation-level Chinese template + the raw diagnostic detail. Never map error categories by matching English substrings.
- Native file-dialog filter labels and update notification text use a small Rust-side static dictionary at `crates/tauri-app/src/commands/native_text.rs`, selected by reading the persisted language snapshot via the existing `SettingsStore` getter. Open blocking dialogs only after releasing the settings lock. OS-provided buttons/decorations stay system-language-controlled.

## Terminology

- Profile → 浏览器配置
- Fingerprint → 浏览器指纹
- Locale → 区域语言

These are display labels only; data fields, IPC values, and CLI args are unchanged.

## Verification

```powershell
# From repo root
npm --prefix crates/tauri-app/ui run build
node --experimental-strip-types crates/tauri-app/ui/src/i18n/dictionaries.test.mjs
cargo test -p settings-store --locked
cargo check --workspace --locked
```

From `crates/tauri-app/ui`:

```powershell
npx playwright test --config playwright.config.ts
```

Playwright mocks Tauri IPC; it cannot replace `settings.json` actual disk writes, native file-filter names, or update prompt verification. Those require isolated manual acceptance.
