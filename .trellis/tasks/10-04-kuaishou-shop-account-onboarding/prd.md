# PRD — 快手小店账号建号向导

## Goal（目标 / 用户价值）

在「快手 › 小店」页提供一条**小店账号专用的建号流程**：点「添加账号」打开向导，输入名称与代理 → 创建环境 → **在向导内扫码登录**（浏览器窗口不出现在用户眼前）→ 自动读出快手ID/昵称/头像 → 完成。运营者按「账号」思考，一次完成建号，全程不离开向导。

## Background（已确认事实）

见 `research/evidence.md`。要点：
- **账号即环境**：一个浏览器环境就是一个小店账号；不复用 `business_accounts` 手工登记表。
- 指纹一致性机制已存在（`fingerprint_generate` + `fingerprint_reconcile` + `fingerprint_locale_for_country`），按代理出口地理对齐即可。
- 小店登录的二维码目前**只在真实浏览器窗口显示**；driver 的 `login()` 只等「已登录」标记，不抓二维码。
- `AuthPhase` 已含 `RestoringHeadless` 语义，但**driver 层从不自己切 headless**；隐藏/还原窗口属上层职责。
- 截图能力已存在（driver `screenshot(profileId)` → base64 PNG）。
- 身份读取已存在（`KuaishouIdentityProvider` + `kuaishou_identity_detect`）。
- 初始化（主体采集 / 切片权限）已有「识别到有效账号后自动补做」机制。

## Requirements（已收敛）

- **R1** 小店页「添加账号」打开**小店建号向导**（独立弹窗），不再复用通用「新建浏览器环境」弹窗。
- **R2** 向导字段：**名称（必填）+ 代理（可选）**；指纹自动随机生成并按代理出口地理自动对齐；不暴露指纹字段。
- **R3** 向导内完成登录：创建环境后以「有头但窗口隐藏到屏幕外/最小化」启动，**在向导内定时截图二维码**供用户扫码；不弹出可见浏览器窗口。
- **R4** 登录成功后自动读出快手ID/昵称/头像并在向导内显示成功态；用户点「完成」关闭向导。
- **R5** 初始化（Subject / Slice）沿用既有自动补做，向导不驱动。
- **R6** 建号成功后小店列表立即出现该账号（头像 + 名称 + 快手ID + 状态）。
- **R7** 取消/中断语义明确：未创建前取消＝无副作用；创建后取消＝保留环境并关闭隐藏窗口（向导提示「账号已创建，可稍后在小店列表继续登录」）。
- **R8** 重复检测：读到身份后若同一快手ID已存在于另一环境，**给出明显警告但不阻断**。

## Out of Scope

- 加货架 / 自动上下车 / 自动发言 / 慧播开播（此前已明确另起）。
- 多账号批量建号。
- 直播伴侣 / 互动账号两个 tab 的业务。
- 复用 / 改造 `business_accounts` 手工登记（本次不动）。

## Acceptance Criteria

- **AC1** 小店页点「添加账号」弹出小店建号向导（含名称、代理字段），不是通用建环境弹窗。
- **AC2** 未填名称时不能进入下一步；代理可选，填写后校验 host。
- **AC3** 创建后向导进入「等待扫码」态，**页面内显示二维码图片**，且**不出现可见的浏览器窗口**（窗口在屏幕外/最小化）。
- **AC4** 用户扫码完成后，向导自动显示快手昵称/头像/快手ID，并出现「完成」按钮。
- **AC5** 点「完成」关闭向导后，小店列表出现该账号且头像/快手ID/状态正确。
- **AC6** 创建后取消（不扫码）关闭向导时，环境仍保留，小店列表能看到该账号且状态为未识别。
- **AC7** 指纹的 locale/timezone/country 与所选代理出口地理一致（有代理时）。
- **AC8** 读到与另一环境重复的快手ID时，向导显示警告文案，但仍可完成。
- **AC9** 向导内截图轮询在登录成功或向导关闭后停止（不泄漏定时器 / 不持续截图）。

## Key Decisions

| # | 决策 | 结论 |
|---|---|---|
| D1 | 账号↔环境关系 | **账号即环境**，不引入独立账号实体、不写 `business_accounts` |
| D2 | 向导深度 | **一步到位**（命名→创建→扫码→读身份→完成） |
| D3 | 创建参数 | **名称 + 代理**；指纹自动随机 + 按代理一致性对齐 |
| D4 | 登录收尾 | 向导内等到登录完成，轮询身份检测 |
| D5 | 二维码呈现 | 二维码显示在**向导内**；浏览器**窗口隐藏到屏幕外/最小化**（非 headless） |
| D6 | 重复账号 | **提示不阻断** |
| D7 | 初始化 | 沿用既有自动补做，向导不驱动 |

## Risks / Deferred

- **风险 R-a**：「窗口移出屏幕/最小化」的实现方式（窗口位置 vs `--headless=new`）与 `chromix` 启动参数契合度需在实现中验证；不可见性以 AC3 的可观测结果为准。
- **风险 R-b**：二维码在页面的位置/大小需裁剪，若页面改版可能取不到二维码区域 → 退化为「整页截图」让用户自行扫。
- **风险 R-c**：截图轮询频率与登录超时（`KS_LOGIN_TIMEOUT`）需对齐，避免长期截图。
- **待定**：向导关闭后是否自动关掉隐藏的浏览器窗口（倾向「是」，避免残留进程）。
